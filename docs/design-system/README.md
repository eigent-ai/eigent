# Eigent Design System Documentation

> **Status: design review passed.** This package is the implementation contract
> for the next design-system migration. It documents the destination and the
> migration work; it does not imply that production components already use the
> new system.

The usage page is generated from the checked-out production source. It includes
counts and call sites, a machine-readable JSON snapshot, and a suggested
migration diff. Regenerate it after rebases and after every migration phase so
the report remains evidence rather than a manually maintained estimate.

## Build and verify

```bash
npm run build:design-system
npm run check:design-system
```

`build:design-system` runs the source scanner, compiles the viewer CSS, and
builds both HTML viewers. `check:design-system` additionally runs the Tailwind 4
sentinel compile, which catches missing design-system utilities that an ordinary
Vite build can overlook.

Generated files are committed review artifacts:

- `current-token-usage/index.html`
- `current-token-usage/usage-report.json`
- `current-token-usage/MIGRATION_DIFF.md`
- `current-token-usage/baseline.html`
- `new-design-system-plan/index.html`
- `viewer.generated.css`

## Working rule

The approved plan is normative for migration decisions. The current-usage
report is descriptive and changes with the codebase. Feature work should not
introduce new legacy aliases while migration is underway; required exceptions
must be added to the exception registry with an owner and removal condition.
